Scope: every module reviewed against the current tree (0.46.0), with the
deepest pass on the **data-building and relationship-building core** —
graph, dossier, dedup, skeptic, edgar, news, research, universe, signals,
usage, and the engine's evidence flow — plus targeted spot-checks of
paper_journal, llm, ratelimit, state, the dashboard's write surface, and

## 1. What is genuinely excellent (keep doing this)

- **Paper-only by construction** holds up under inspection: `prices.py`
  contains no order methods, the journal is a dataclass log, and nothing
  else touches a broker.
- **Forward-record discipline is the best part of the system.**
  `SCORING_VERSION` stamped on every snapshot and signal row, per-record
  `scored_by_model`/`reviewed_by_model`, the model-provenance warning on
  swap, `threshold_in_force`/`min_sources_in_force` stamped per signal,
  daily passes marked done only after success, weekend marks skipped for
  the documented join-truncation reason, strategy-generation stamping on
  trades. This is publication-grade experimental hygiene.
- **Evidence-loss paranoia in the engine.** The definitive-vs-deferred
  outcome contract, throttled-to-empty returning "retry later" instead of
  registering the fingerprint, `would_allow`/`record`-only-on-definitive,
  the pending-proposal cache across a deferred skeptic call, per-symbol
  and per-filing exception isolation. Reads like someone was burned once
  and never again.
- **The budget system.** Per-category caps plus a *reservation* (not a
  ceiling) for synthesis, with the measured-live failure ("synthesis had
  never run in the entire life of the system") documented at the
  constructor. Unknown models priced at the most expensive entry.
- **Data-hygiene filters with live pedigree**: lender phrases, biography
  edges, junk-candidate retro-blocking, `name_matches_ticker` (the
  Advantest→ATRO guard), placeholder tickers, non-company keywords,
  near-duplicate headline collapse.
- **EDGAR depth**: exhibits-first 8-K text, item-code expansion in the
  headline, structured Form 4 summaries, head+tail truncation, CIK
  liveness pruning of dead symbols.
- **Research is leads-only, never edges** — the one place a hallucination
  could mint a trade-gating fact is architecturally closed off.
- **The docstrings.** The codebase is its own ops journal; nearly every
  constant carries the live incident that calibrated it. This is worth
  more than any single feature.

## 2. Needs fixing — verified against current code

### 2.1 HIGH: the synthesis pass is not actually wired into the trade gate

The README (point 6) and `DossierSynthesizer`'s docstring say the daily
whole-evidence-body verdict **caps** the arithmetic score — veto and trim,
never lift. Three connected gaps mean that in practice it barely gates
anything:

1. **The merge path never sees it.** `signals.evaluate()` reads only
   direction/sources/confidence×magnitude; `_update_dossier` →
   `evaluate` → `_fire_signal` runs on the raw arithmetic aggregate. A
   synthesis veto (`already_priced_in`, direction disagreement) at the
   morning decay pass does not prevent a signal firing that afternoon
   when one more evidence item merges — `merge_evidence`'s `_aggregate`
   recomputes confidence/magnitude from evidence and the cap is gone.
   The cap is enforced exactly once a day, transiently, on the decay
   path only (`engine.py:2823-2834`).
2. **The verdict isn't persisted on the common path.** `_decay_one` saves
   only when the *pre-synthesis* decay fingerprint changed
   (`engine.py:2803-2807`); `_apply_synthesis` then mutates
   `synthesis_at/note/catalyst/distinct_fact_count/already_priced_in`
   and the capped scores in memory. Unless a signal fires (fresh episode)
   or expires in the same pass, nothing saves — the dashboard shows
   stale/empty synthesis fields and `Dossier`'s claim that verdicts are
   "recorded even when the verdict changes nothing, so the pass's actual
   effect on outcomes is measurable" does not hold.
3. **The snapshot doesn't record it.** `status.snapshot_dossier`
   (status.py:389) writes neither the synthesis fields nor the capped
   score, so `dossier_snapshots.jsonl` — the primary forward dataset —
   records the *uncapped* arithmetic score while decay-path trades gate
   on the capped one. The record can't measure the one pass built to
   answer overlap/coherence/priced-in.

Sharpening the irony: the add-on config runs extraction/dossier/skeptic
on `claude-haiku-4-5` and reserves `claude-opus-5` for synthesis — the
premium model is spent on the pass whose output is mostly discarded,
while the hard trade-gating judgments run on the cheapest tier.

Fix shape: persist the dossier after every synthesis run; record the
verdict's cap fields; have `evaluate()` (or `_update_dossier` before
evaluating) apply a still-fresh cap (e.g. synthesis younger than ~36h)
to the score; add synthesis columns to `snapshot_dossier`. Each piece is
small; together they make README point 6 true.

### 2.2 HIGH: paid relationship extraction re-billed while dossier budget is exhausted

`_process_filing` (engine.py:1173) runs `_extract_relationships` (a paid
call, up to ~150k chars of filing text) *before* `_process_evidence`, and
the dedup fingerprint is registered only when scoring completed
definitively. When the dossier-category budget is exhausted (or the
skeptic call fails transiently), the filing stays unregistered — and the
next EDGAR poll (default 900s) re-fetches it and **re-runs extraction**.
The category split makes this worse than before it existed: extraction's
share can be intact while dossier's is gone, so every 10-K/10-Q inside
the 14-day lookback gets re-extracted every 15 minutes for the rest of
the day, burning the extraction share on filings already extracted.
`graph.add` dedupes so there's no correctness harm — it is pure spend.

Fix: a persisted per-accession "extracted" marker (the backfill path
already has exactly this in `backfill_state`), checked before extracting
on the poll path.

### 2.3 MEDIUM: corrupt-file wipe paths for the highest-value data

`DossierStore.load` (dossier.py:158), `RelationshipGraph.__post_init__`
(graph.py:43), and `JsonState.__init__` (state.py:15) all degrade an
unreadable/corrupt file to "start fresh" — and the next save overwrites
the original. For a dossier that is the permanent loss of accumulated
evidence; for the graph it is compounded by `backfill_state` still
saying "done", so edges would not be re-extracted until each symbol's
next annual 10-K (the dashboard's rebuild-graph tool exists as manual
recovery, if anyone notices). Writes are atomic (tmp+replace) so the
likely corruption vector is small, but the failure mode is silent total
loss. Fix: rename the unreadable file to `<name>.corrupt-<timestamp>`
and warn loudly before starting fresh; consider a daily `.bak` rotation
for `data/` (it is all small JSON).

### 2.4 MEDIUM: graph edges never upgrade and never age

`graph.add` (graph.py:73) returns False on an existing
(from, to, rel_type) without refreshing confidence/description/source.
A weak passing-mention edge at 0.55 permanently blocks a later
quantified concentration disclosure ("GM accounted for 25% of net
sales", 0.95) from raising it — and `DISCLOSED_LINK_CONFIDENCE = 0.85`
gates `has_disclosed_link_evidence`, which decides which corroboration
bar `signals.evaluate` applies. The strongest structural edge in the
system can be held below the bar forever by whichever extraction
happened to run first. The reverse is also unhandled: relationships end
(customer lost — itself a tradeable event), but edges have no aging, no
re-verification cadence, and `extracted_at` is never refreshed.

Fix: on duplicate add, keep the max confidence (refresh
description/source/extracted_at when the new extraction is stronger);
surface edges not re-confirmed by any filing in N months on the
dashboard.

### 2.5 MEDIUM: restart-volatile retry state resurrects a fixed bug class

`_pending_proposals` and `_handled_outcomes` (engine.py:344-365) are
in-memory by design, and both sliding-window limiters are too. The HA
deployment restarts several times a day. A restart after a
refuted/not-new outcome forgets the marker, so a sibling-deferral retry
re-pays propose+skeptic — and a second, nondeterministic skeptic run can
accept what the first refuted: the exact bug class the July audit fixed,
reintroduced through the restart door. A restart between propose and
skeptic re-pays the proposal; a restart resets propagation cooldowns.
Fix: persist both dicts (wall-clock stamps, they are small) to
`JsonState`; optionally the limiter windows too.

### 2.6 MEDIUM-LOW: independence key is too blunt for direct filings

`independence_key` (dossier.py:207) collapses all direct EDGAR evidence
of one form to a single source ("SEC EDGAR (8-K)"). Two genuinely
distinct 8-K events months apart — an Item 1.01 contract award in May
and an Item 2.02 guidance cut in July — can never corroborate each
other, and a filings-only dossier caps at roughly the number of distinct
form types. The inline comment defends this ("two 8-Ks close together
are more likely one unfolding story"), which is right for *close
together* and wrong at a distance. The principled fix is 2.1 — synthesis
`distinct_fact_count` wired into the gate is exactly this judgment made
by something that can read the items; a cheap alternative is including
the filing month or item code in the key for 8-Ks.

### 2.7 Smaller verified items

- **Updater and skeptic prompts never state today's date.** Both are
  asked to judge "old/already-priced-in news treated as new"; evidence
  text carries `published_at`, but with no reference date the age is
  uncomputable (models assume "now" is their training cutoff). The
  synthesizer already gets `Today:` — one line fixes the other two.
- **The cost meter ignores cache tokens.** `usage.record` prices
  `input_tokens`/`output_tokens` only; cache-write (1.25×) and
  cache-read (0.1×) tokens from `cacheable_system` blocks are never
  priced. Small absolute undercount, but the budget is the safety net.
- **Near-duplicate window is same/previous UTC day** — a reworded
  republish two-plus days later (weekend syndication) can still buy a
  second "independent" source. Mitigated by the updater's not-new check
  and the skeptic; noted, not urgent.
- **Gap-through-stop fills are optimistic.** `PriceBar` has no session
  `open`, so a LONG that gaps far below the stop and recovers intraday
  fills at min(stop, close) — the close — while a real stop would have
  filled near the open. Adding `open` to the bar (IB has it; Finnhub
  /quote's `o`) and using it for gap-day fills removes the last
  optimistic bias in the fill model.
- **Strategy tension, not a bug:** `enable_auto_accept_candidates=true`
  with `auto_accept_max_per_day=20` (config.py:454,477) sits oddly
  against three consecutive audits recommending a frozen universe for a
  clean 90-day measurement window. Generation stamping segments the
  *trade* record but universe churn still confounds the snapshot
  cross-section. Worth a deliberate decision either way.

## 3. What to add next (highest value for the data/relationship core)

1. **Finish wiring synthesis** (2.1). This is the single biggest gap
   between the documented design and the running system, and it is the
   direct answer to "N items or N facts" — the question the whole
   corroboration machinery bends around.
2. **Skeptic-effect readout.** Every evidence record already stores
   `proposed_confidence/proposed_magnitude` next to the post-skeptic
   numbers — instrumentation built precisely to measure whether the
   skeptic earns its 2× cost — and nothing reads it. A small report
   (refutation rate, adjustment distribution, split direct vs propagated,
   split by model) over the dossier files would answer whether Haiku's
   judgment is good enough for the trade-gating tier, which is now the
   live question given the model retune.
3. **Graph lifecycle** (2.4): upgrade-on-stronger-disclosure, staleness
   surfacing, and a dashboard view of per-edge last-confirmed dates.
4. **Extraction done-markers** (2.2) and **persisted retry caches**
   (2.5) — both small, both pure cost/correctness wins under the
   several-restarts-a-day reality.
5. **Corrupt-file quarantine + data/ backup rotation** (2.3).
6. **Today's date in the two per-item prompts** (2.7).
