## 1. What is genuinely excellent (keep doing this)

- **Paper-only by construction** holds up under inspection: `prices.py`
  contains no order methods, the journal is a dataclass log, and nothing
  else touches a broker.
- **Forward-record discipline is the best part of the system.**
  `SCORING_VERSION` stamped on every snapshot and signal row, per-record
  `scored_by_model`/`reviewed_by_model`, the model-provenance warning on
  swap, `threshold_in_force`/`min_sources_in_force` stamped per signal,
  daily passes marked done only after success, weekend marks skipped for
  the documented join-truncation reason, strategy-generation stamping on
  trades. This is publication-grade experimental hygiene.
- **Evidence-loss paranoia in the engine.** The definitive-vs-deferred
  outcome contract, throttled-to-empty returning "retry later" instead of
  registering the fingerprint, `would_allow`/`record`-only-on-definitive,
  the pending-proposal cache across a deferred skeptic call, per-symbol
  and per-filing exception isolation. Reads like someone was burned once
  and never again.
- **The budget system.** Per-category caps plus a *reservation* (not a
  ceiling) for synthesis, with the measured-live failure ("synthesis had
  never run in the entire life of the system") documented at the
  constructor. Unknown models priced at the most expensive entry.
- **Data-hygiene filters with live pedigree**: lender phrases, biography
  edges, junk-candidate retro-blocking, `name_matches_ticker` (the
  Advantest→ATRO guard), placeholder tickers, non-company keywords,
  near-duplicate headline collapse.
- **EDGAR depth**: exhibits-first 8-K text, item-code expansion in the
  headline, structured Form 4 summaries, head+tail truncation, CIK
  liveness pruning of dead symbols.
- **Research is leads-only, never edges** — the one place a hallucination
  could mint a trade-gating fact is architecturally closed off.
- **The docstrings.** The codebase is its own ops journal; nearly every
  constant carries the live incident that calibrated it. This is worth
  more than any single feature.

## 2. Needs fixing — verified against current code

### 2.1 HIGH: the synthesis pass is not actually wired into the trade gate

The README (point 6) and `DossierSynthesizer`'s docstring say the daily
whole-evidence-body verdict **caps** the arithmetic score — veto and trim,
never lift. Three connected gaps mean that in practice it barely gates
anything:

1. **The merge path never sees it.** `signals.evaluate()` reads only
   direction/sources/confidence×magnitude; `_update_dossier` →
   `evaluate` → `_fire_signal` runs on the raw arithmetic aggregate. A
   synthesis veto (`already_priced_in`, direction disagreement) at the
   morning decay pass does not prevent a signal firing that afternoon
   when one more evidence item merges — `merge_evidence`'s `_aggregate`
   recomputes confidence/magnitude from evidence and the cap is gone.
   The cap is enforced exactly once a day, transiently, on the decay
   path only (`engine.py:2923-2937`).
2. **The verdict isn't persisted on the common path.** `_decay_one` saves
   only when the *pre-synthesis* decay fingerprint changed
   (`engine.py:2906-2910`); `_apply_synthesis` then mutates
   `synthesis_at/note/catalyst/distinct_fact_count/already_priced_in`
   and the capped scores in memory. Unless a signal fires (fresh episode)
   or expires in the same pass, nothing saves — the on-disk dossier
   keeps stale or empty synthesis fields (and no dashboard surface
   renders them at all) and `Dossier`'s claim that verdicts are
   "recorded even when the verdict changes nothing, so the pass's actual
   effect on outcomes is measurable" does not hold.
3. **The snapshot doesn't record it.** `status.snapshot_dossier`
   (status.py:509) writes neither the synthesis fields nor the capped
   score, so `dossier_snapshots.jsonl` — the primary forward dataset —
   records the *uncapped* arithmetic score while decay-path trades gate
   on the capped one. The record can't measure the one pass built to
   answer overlap/coherence/priced-in.

Sharpening the irony: the add-on config runs extraction/dossier/skeptic
on `claude-haiku-4-5` and reserves `claude-opus-5` for synthesis — the
premium model is spent on the pass whose output is mostly discarded,
while the hard trade-gating judgments run on the cheapest tier.

Fix shape: persist the dossier after every synthesis run; record the
verdict's cap fields; have `evaluate()` (or `_update_dossier` before
evaluating) apply a still-fresh cap (e.g. synthesis younger than ~36h)
to the score; add synthesis columns to `snapshot_dossier`. Each piece is
small; together they make README point 6 true.

### 2.2 HIGH: paid relationship extraction re-billed while dossier budget is exhausted

`_process_filing` (engine.py:1189) runs `_extract_relationships` (a paid
call, up to ~150k chars of filing text) *before* `_process_evidence`, and
the dedup fingerprint is registered only when scoring completed
definitively. When the dossier-category budget is exhausted (or the
skeptic call fails transiently), the filing stays unregistered — and the
next EDGAR poll (default 900s) re-fetches it and **re-runs extraction**.
The category split makes this worse than before it existed: extraction's
share can be intact while dossier's is gone, so every 10-K/10-Q inside
the 14-day lookback gets re-extracted every 15 minutes for the rest of
the day, burning the extraction share on filings already extracted.
`graph.add` dedupes so there's no correctness harm — it is pure spend.

Fix: a persisted per-accession "extracted" marker (the backfill path
already has exactly this in `backfill_state`), checked before extracting
on the poll path.

### 2.3 MEDIUM: corrupt-file wipe paths for the highest-value data

`DossierStore.load` (dossier.py:158), `RelationshipGraph.__post_init__`
(graph.py:43), and `JsonState.__init__` (state.py:15) all degrade an
unreadable/corrupt file to "start fresh" — and the next save overwrites
the original. For a dossier that is the permanent loss of accumulated
evidence; for the graph it is compounded by `backfill_state` still
saying "done", so edges would not be re-extracted until each symbol's
next annual 10-K (the dashboard's rebuild-graph tool exists as manual
recovery, if anyone notices). [0.47.0: the rolling graph refresh
re-reads ~10 symbols/day, so a wiped graph now repopulates over roughly
a month for the full universe instead of waiting on annual 10-Ks —
recovery, but still silent recovery; the dossier and state losses are
unchanged.] Writes are atomic (tmp+replace) so the
likely corruption vector is small, but the failure mode is silent total
loss. Fix: rename the unreadable file to `<name>.corrupt-<timestamp>`
and warn loudly before starting fresh; consider a daily `.bak` rotation
for `data/` (it is all small JSON).

### 2.4 MEDIUM: graph edges never upgrade and never age

`graph.add` (graph.py:73) returns False on an existing
(from, to, rel_type) without refreshing confidence/description/source.
A weak passing-mention edge at 0.55 permanently blocks a later
quantified concentration disclosure ("GM accounted for 25% of net
sales", 0.95) from raising it — and `DISCLOSED_LINK_CONFIDENCE = 0.85`
gates `has_disclosed_link_evidence`, which decides which corroboration
bar `signals.evaluate` applies. The strongest structural edge in the
system can be held below the bar forever by whichever extraction
happened to run first. The reverse is also unhandled: relationships end
(customer lost — itself a tradeable event), but edges have no aging, no
re-verification cadence, and `extracted_at` is never refreshed.
[0.47.0's rolling re-extraction gives filings a ~monthly re-READ
cadence, but `graph.add` still returns False on an existing
(from, to, rel_type) without touching it, so a re-read can only add new
edges — confidence, description, source and `extracted_at` on an
existing edge stay frozen at first extraction, and the upgrade block
above stands in full.]

Fix: on duplicate add, keep the max confidence (refresh
description/source/extracted_at when the new extraction is stronger);
surface edges not re-confirmed by any filing in N months on the
dashboard.

### 2.5 MEDIUM: restart-volatile retry state resurrects a fixed bug class

`_pending_proposals` and `_handled_outcomes` (engine.py:344-365) are
in-memory by design, and both sliding-window limiters are too. The HA
deployment restarts several times a day. A restart after a
refuted/not-new outcome forgets the marker, so a sibling-deferral retry
re-pays propose+skeptic — and a second, nondeterministic skeptic run can
accept what the first refuted: the exact bug class the July audit fixed,
reintroduced through the restart door. A restart between propose and
skeptic re-pays the proposal; a restart resets propagation cooldowns.
Fix: persist both dicts (wall-clock stamps, they are small) to
`JsonState`; optionally the limiter windows too.

### 2.6 MEDIUM-LOW: independence key is too blunt for direct filings

`independence_key` (dossier.py:207) collapses all direct EDGAR evidence
of one form to a single source ("SEC EDGAR (8-K)"). Two genuinely
distinct 8-K events months apart — an Item 1.01 contract award in May
and an Item 2.02 guidance cut in July — can never corroborate each
other, and a filings-only dossier caps at roughly the number of distinct
form types. The inline comment defends this ("two 8-Ks close together
are more likely the same unfolding story"), which is right for *close
together* and wrong at a distance. The principled fix is 2.1 — synthesis
`distinct_fact_count` wired into the gate is exactly this judgment made
by something that can read the items; a cheap alternative is including
the filing month or item code in the key for 8-Ks.

### 2.7 Smaller verified items

- **Updater and skeptic prompts never state today's date.** Both are
  asked to judge "old/already-priced-in news treated as new"; evidence
  text carries `published_at`, but with no reference date the age is
  uncomputable (models assume "now" is their training cutoff). The
  synthesizer already gets `Today:` — one line fixes the other two.
- **The cost meter ignores cache tokens.** `usage.record` prices
  `input_tokens`/`output_tokens` only; cache-write (1.25×) and
  cache-read (0.1×) tokens from `cacheable_system` blocks are never
  priced. Small absolute undercount, but the budget is the safety net.
- **Near-duplicate window is same/previous UTC day** — a reworded
  republish two-plus days later (weekend syndication) can still buy a
  second "independent" source. Mitigated by the updater's not-new check
  and the skeptic; noted, not urgent.
- **Gap-through-stop fills are optimistic.** `PriceBar` has no session
  `open`, so a LONG that gaps far below the stop and recovers intraday
  fills at min(stop, close), which on a deep gap day sits well above
  where a real stop would have filled — near the open. Adding `open`
  to the bar (IB has it; Finnhub
  /quote's `o`) and using it for gap-day fills removes the last
  optimistic bias in the fill model.
- **Strategy tension, not a bug:** `enable_auto_accept_candidates=true`
  with `auto_accept_max_per_day=20` (config.py:504,527) sits oddly
  against three consecutive audits recommending a frozen universe for a
  clean 90-day measurement window. Generation stamping segments the
  *trade* record but universe churn still confounds the snapshot
  cross-section. Worth a deliberate decision either way.

# Addendum — live diagnostics bundle, 2026-08-07 15:27 UTC

The bundle turns several code-level findings into measured facts and
surfaces one systemic dynamic that outranks everything in the original
ranking except the synthesis wiring — which it also proves live.

## A1. The synthesis bypass is happening daily, on real trades

The signal-episode ledger shows the split-brain in action, dozens of
times. Every night the decay pass runs Opus synthesis, which vetoes the
big dossiers — that is what every `expired unopened ... (score 0.000 <
bar)` row is: 0.000 is a synthesis veto (`already_priced_in` or direction
disagreement), not decay. The same dossiers then re-fire on the Haiku
merge path — which never consults synthesis — and open. Textbook case:
**DCO vetoed to 0.000 at 2026-08-07T00:21, re-fired at 11:23 at score
0.947, paper trade opened.** BWEN: vetoed 08-03 twice, opened 08-04,
opened again 08-06. The system's most expensive, most-carefully-prompted
judgment is being systematically overridden within hours, every day.
Also note: `_decay_one` skips synthesis for symbols with an open trade,
so once a trade opens on an uncapped score, synthesis never re-examines
that dossier while it is open. The ledger reason string should also say
*synthesis veto (already priced in)* rather than printing the zeroed
score as if decay produced it.

## A2. Universe growth + ecosystem fan-out has saturated the scoring system

The board: 14 dossiers ≥ 0.65, several at a perfect 1.000/1.000, source
counts of 20–26, masses like 19.87/0.00 — and **30 open paper trades, 51
tradeables, ~28 of them LONG**. That is not a research system finding
occasional mispricings; it is one giant correlated LONG bet — the exact
failure the 2026-07 universe redesign was built to escape. The mechanism
is a compounding chain, each link verified in code:

1. **Auto-accept at its 20/day cap** (config.py:527 and the add-on
   default alike; hit again today at 15:07) has grown the universe to
   330 symbols — 279 anchors, 144 auto-accepted, 1,649 candidates
   queued. Anchor accepts are deliberately liberal: no seen-count, and —
   unlike tradeables — **no `name_matches_ticker` check**
   (engine.py:1706-1726), so a misresolved ticker can become an
   anchor unchecked.
2. **`guess_ecosystem` classifies each accepted candidate into the
   discoverer's ecosystem** (universe_screen.py:182). Result, visible in
   the bundle: MRK/BMY/MRNA/MCK/CAH/APO/CVS/AZN/VRTX filed under
   *semi_equipment*; JPM/T/UAL/AAL/DAL under *defense_tier2*; WFC/USB
   under *medtech_supply*; PEP/DG/NOK under *transport_logistics*.
3. **Ecosystem propagation** (`ECOSYSTEM_LINK_CONFIDENCE = 0.25`) fans
   every edge-less anchor's news to every tradeable in its — frequently
   wrong — ecosystem, 1 item per link per 6h. With ~279 anchors this is
   the bulk of the 3,872 dossier calls ($14.35) made today.
4. **Haiku accepts enough of it.** Each accepted item is small (0.2–0.5
   confidence), but `independence_key` mints a fresh independent-source
   slot per (origin, publisher) pair — the fix that was correct for
   *disclosed* counterparties now counts every fanned-in anchor as
   independent corroboration.
5. **The aggregate saturates.** At S=21 sources the magnitude multiplier
   is ×2.1 (log2 bonus) and the confidence bonus is at its +0.25 cap on
   top of a max-item base — so any dossier with one strong item plus
   fan-out mass pins at ~1.0/1.0. Uniformly positive AI-capex sector news
   means near-zero opposing mass, so the contest discount never engages.

The one pass designed to catch exactly this — synthesis counting
*distinct facts* — is the pass being bypassed (A1). The two findings are
one problem.

**Recommended containment, config-only, before any code ships:**
`auto_accept_anchors=false` (or the whole auto-accept off), and
`enable_ecosystem_propagation=false` until classification is
trustworthy. Code-level: restrict ecosystem fan-out to *curated* anchors
(a guessed ecosystem is not an association claim worth 4 LLM calls/day
per tradeable); make ecosystem-propagated items contribute decay mass
but **not** independence-key slots (they are association, not
corroboration); add the name-match guard to anchor accepts.

## A3. Tradeable-quality regressions visible on the board

Auto-accepted tradeables now include a preferred-stock line (SCE-PN,
score oscillating 0.96→0.00 nightly on fanned-in utility news), foreign
OTC ADR lines (SCRNY — cap unknown at trade time), CVV at $55M (below
the $75M floor), a bankrupt-parent solar name (SPWR, SHORT at $44M,
assumes-borrow), and an airline classified as defense_tier2 (RJET).
The accept-time filter for the first class already ships:
`is_common_equity` (engine.py:211, in the tree this audit reviewed, its
comment citing this exact SCE-PN/SCRNY incident) blocks hyphen/dot
share classes, preferreds and five-letter Y/F OTC ADRs from tradeable
accepts — but it blocks *new* accepts only, and what the board shows
are accepts that predate it. The fix is retroactive: sweep
`accepted_candidates` with the same predicate and demote the hits to
anchor. CVV and SPWR are common equity below the $75M
`universe_min_market_cap_musd` floor — that is the monthly prune
screen's job to flag.

## A4. The IB feed is half-dead and stalling the whole engine

Every price lookup 15:01–15:27 failed at exactly ~21s spacing = the 20s
`_IB_CALL_TIMEOUT_SEC` plus the 1s gap: the Gateway accepts connections
(`isConnected()` true, so `ensure_connected` never reconnects) but its
data farms hang every request. The engine is a single task, so with 30
open positions a marking poll spends 30 × 21s ≈ **10.5 minutes hung on
IB timeouts out of every 15-minute entry-cadence cycle** — ingestion,
decay, and entries all wait behind it. Finnhub then fills the marks in
(price_marks has today's rows), so the data survives, but the engine is
running at a fraction of its cadence and the log is pure ERROR spam.
Fix: a data-level circuit breaker (N consecutive IB failures → skip IB
for 30 min and go straight to Finnhub), plus one summary WARNING instead
of per-symbol ERROR. Operationally today: restart the Gateway / check
its market-data farm status.

## A5. The position cap is not enforced

`_try_open_from_signal` sizes every entry at
`initial_trading_capital / max_concurrent_positions` (EUR 333) but never
checks the open count: the bundle shows **30 open positions on a
"15-slot" EUR 5,000 account — EUR 10,000 notional, 2× the modeled
capital**. Either enforce the cap at entry (skip when full — and record
the skip in the decisions ledger so the event study can score what the
cap cost) or size positions off remaining capacity; as is, the currency
P&L overlay measures a leverage the account model does not claim.

## A6. Budget reality check

$25.05 spent by 15:27 UTC against the $30 cap (call cap 4,083/5,000 —
both live overrides: the shipped defaults the 0.28.1 retune calibrated
are $3.30/day and 3,000 calls, and the bundle's spend exceeds both);
extraction's $10.50 share exhausted (207 calls ≈ the auto-accept flood's
10-K backfills), dossier at $14.35/3,872 Haiku calls — the fan-out bill.
Run-rate ≈ $750/month against the $100/month the 0.28.1 retune targeted.
The A2 containment collapses most of this: fewer anchors and no
misclassified fan-out cuts the dossier category by an estimated 5–10×,
which is budget enough to upgrade the *skeptic* (the judgment that
actually gates merges) a model tier if desired.

## A7. Publisher identity is thinner than the "8 sources" suggests

17,170 dedup fingerprints across **8** distinct source names, with
finnhub.io itself standing in as publisher for 8,337 (~49%) of them —
half the news feed carries one shared source identity. Publisher-based
corroboration is therefore nearly exhausted at 2–3 distinguishable
identities, and effectively all independence now comes from origin
diversity (propagation) — precisely the axis A2 shows being inflated.
Worth knowing when tuning `min_independent_sources*`.

## A8. Measurement stack re-verified against current code

`forward_returns.py` (N_eff, symbol-clustered bootstrap, censoring
accounting), `event_study.py` (episode collapse → outcome precedence →
drift-blocked-vs-opened scorecard) and `exit_analysis.py` (identical
cost arithmetic on both counterfactual legs, gap-through-stop
integrity) all hold up. One stale note: `SCORE_BUCKETS`' top boundary
comment says it matches the 0.65 default threshold; the live threshold
is 0.5 — still answerable (0.5 is a bucket edge), but the comment and
ideally the bucket set should follow the configured threshold. Forward
capture is healthy: snapshots 555 rows (07-23→08-06, no gaps), marks
2,589 rows, decisions 113 rows. The 15 closed trades are all
legacy-generation (old tight grid) — correctly segregated from the new
hold-to-horizon generation, and at n=15 (CI 20–64%) decision-grade for
nothing yet.

## A9. Updated priority order

1. **Config, today**: `auto_accept_anchors=false`,
   `enable_ecosystem_propagation=false` (until A2's code fixes),
   restart/repair the IB Gateway.
2. **Synthesis wiring** (original 2.1) — persist verdicts, cap the merge
   path, snapshot the fields. Proven live by A1.
3. **Corroboration inputs** (A2): ecosystem items → mass only, no source
   slots; fan-out restricted to curated anchors; anchor name-match.
4. **Position-cap enforcement** (A5) and the **IB circuit breaker** (A4).
5. Then the original list: extraction done-markers, persisted retry
   caches, corrupt-file quarantine, edge upgrade/aging, today's-date in
   prompts, snapshot synthesis columns.
